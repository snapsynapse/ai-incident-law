Corrections and source challenges

Evidence-backed corrections and source challenges remain welcome. Include the existing record ID, the disputed field or claim, and the retained or public source supporting the correction. Routine new-record curation is dormant; a correction report does not itself admit a source or renew dates.

Retained admission criteria

These are the criteria used for existing records. A candidate was admitted to the included bucket when all of the following held. They are reproduced from INTENT.md, the authoritative statement, which applies them equally to the steward's own submissions. A correction may cite them when it challenges whether an existing record still meets them.

  1. 1
    There is a public legal or regulatory matter directly involving AI-related conduct, output, or use.
  2. 2
    The matter has at least one primary or reliable secondary public source.
  3. 3
    The matter has resolved to one of: filed proceeding, regulatory action, settlement, judgment, consent decree, or formal investigation disclosure. Press coverage alone is not sufficient.
  4. 4
    The record fields required for publication (jurisdiction, parties, AI-relevance, source URLs, date) are present and consistent.

Retained dataset buckets

included

Meets all four admission criteria. Renders on the main site, appears in the Obligation-First API, and is fetchable by the public MCP.

review

In scope but needs verification, primary-source strengthening, or schema cleanup. Visible in the dataset but flagged.

global

Non-US matters that need translation, jurisdiction-specific interpretation, or additional sourcing. Held; no promotion work is scheduled while frozen.

The correction process

Option 1 -- open an issue (recommended)

Open a GitHub issue with the data label. Include:

  • record ID
  • disputed field or claim
  • supporting public or retained source
  • proposed corrected value

Reports remain available for bounded steward review. There is no promised response time or ongoing curation cadence. Existing source-access limits and admission requirements still apply.

Option 2 -- open a pull request (for contributors comfortable with JSON)

For a bounded correction to an existing record, edit data/data.json following the field shapes documented in docs/data-schema.md. Run npm run build and npm run check locally before opening the PR so URL policy and validation pass.

Read CONTRIBUTING.md for the exact editing rules.

Anchoring to obligations

If a proposed correction concerns a sourced disposition in an existing matter and you can identify which EveryAILaw obligation categories the Determination interpreted or applied, include them as obligation_first_anchors. This is what makes the matter traversable from the PAICE legal graph. If the matter is filed or pending and no sourced adjudicative act exists, leave the field off. Anchors are valid only when the source supports their relationship to a generated Determination.

What we do not accept

  • Speculative AI-risk commentary or ethics statements without legal or regulatory action attached.
  • Internal corporate disputes that have not surfaced publicly.
  • Reputational controversy that has not produced a filing or formal action.
  • Private filings, leaked material, or anonymous tips. Every record must resolve to a public source.
  • Records under non-disclosure or otherwise barred from public reference.
